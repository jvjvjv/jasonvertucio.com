## 2. Signature image

- [x] 2.1 Create `app/Services/Resume/SignatureImageService.php` that loads `resources/resume/signature.png` via GD and produces a brand-blue, background-keyed PNG. The committed source is fully opaque (`alpha histogram: [0 => 82585]`) with a solid `#FFFFFF` background, so alpha is **derived from luminance** — white → fully transparent, dark strokes → fully opaque, near-white anti-aliasing → proportionally translucent — and combined with any alpha the source already carries, so a future RGBA source is not made opaque. Every still-visible pixel is set to `#1B587C`. Returns the PNG bytes with the source pixel dimensions (`imagealphablending(false)` + `imagesavealpha(true)` on the output). Verify with unit tests asserting a stroke pixel comes back `#1B587C`, the white background comes back fully transparent, a mid-luminance source pixel comes back partially transparent, and a source pixel that was already transparent stays transparent.
- [x] 2.2 Add EMU sizing to `SignatureImageService`: `cy = 1828800` (2 inches) and `cx = round(1828800 * srcWidth / srcHeight)`, computed from the loaded image, never hardcoded. Verify with unit tests asserting `cy === 1828800` for the real 199×415 source with `cx` ≈ 877,000, and that a synthetic square fixture yields `cx === cy`.
- [x] 2.3 Make signature failure non-fatal: a missing file, an unreadable file, or a GD failure returns null and writes a `Log::warning` naming the reason. ## 7. PDF conversion and font weights (added during apply)

- [x] 7.1 Add `libreoffice-writer` to the Dockerfile's `development` stage. Every `generatePdf()` shells out to `libreoffice`, which the image never installed, so PDF conversion failed in the container with `sh: libreoffice: not found` while DOCX generation succeeded — surfacing as "Candidate approved, but document generation failed". Production is not Docker and keeps using its host LibreOffice, so the `base` and `production` stages are deliberately untouched. Verify with `docker compose build app` then `docker exec jv-app which libreoffice`.
- [x] 7.2 Re-embed real font weights in `resources/resume/2026 template.docx`. Every Montserrat and Josefin Sans face was the **Thin** weight, including the ones in the Bold slots, so the six bold-requesting styles (`Title`, `Heading1`, `Heading2`, `JobTitle`, `Strong1`, `Heading2Char`) had no bold outline and were rendered as synthetic bold. Replaced with real Montserrat Regular/Bold/Italic/BoldItalic and Josefin Sans Bold/Italic, instantiated from the upstream variable fonts. Verified: synthetic-bold operations in the generated PDF drop from 27 to 0, `pdffonts` reports real `JosefinSans-Bold` and `Montserrat-Regular` faces, and the resume stays 4 pages.
- [x] 7.4 Omit the `# Summary` heading. It sits directly under the letterhead, where "SUMMARY" repeats what its position already says and stacks a second rule against the letterhead's own. `ResumeMarkdownComposer` no longer emits it, and `MarkdownToOpenXmlConverter` suppresses a `# Summary` h1 outright so targeted resumes — whose stored markdown carries it from the agent prompt — render identically without needing their content rewritten. Verify with the converter and composer unit tests plus a regenerated resume showing the summary flowing straight from the letterhead.
- [x] 7.5 Lay the cover letter sign-off out the way it would be typed, and anchor the signature to the name. Structure: a blank line, the closing, a blank signing line, then the typed name — with the 2in signature attached to the **name** paragraph as a floating image (`wp:anchor` + `wrapNone` + `allowOverlap`) positioned above it. Anchoring to the name rather than to a spacer keeps the placement stable, since the signature travels wherever the name lands, and the sign-off costs the page a few short lines instead of the signature's full height.

      Placement was set against a hand-placed reference: `SIGNATURE_RISE = -1143000` EMU (1.25in above the name paragraph) and `SIGNATURE_GAP = 720` twentieths of a point (a half-inch blank line, pinned `lineRule="exact"` so it does not drift with the template's line spacing).

      Tune these by looking at a rendered page, not by arithmetic. Two traps: the source PNG's ink box is 138x365 inside a 199x415 image, so any scale derived from the image box is ~44% off; and the ink starts 0.149in below the image's top edge. Reference screenshots are usually cropped, which makes the signature's apparent height useless as a scale — use the text line height as a scale-invariant ruler and compare renders side by side before calling it a fit.

      Capacity: a 13-paragraph letter fits on one page, and at the tightest fit the signature renders complete at the page foot without clipping. Earlier attempts — inline at 2in, inline at 1.5in with keepNext, and a floating version placed in a spacer paragraph — are all superseded.
