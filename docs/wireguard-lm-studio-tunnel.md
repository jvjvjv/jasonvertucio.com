# WireGuard Tunnel for Local LM Studio

## Overview

This guide covers connecting a local [LM Studio](https://lmstudio.ai/) instance to the production server using a WireGuard VPN tunnel. This is necessary when the local machine is behind NAT (typical home internet) and cannot accept inbound connections directly.

The production server acts as the WireGuard **server** because it has a public IP. The local machine running LM Studio acts as the WireGuard **client** and initiates the outbound connection. Once the tunnel is active, the production server can reach LM Studio through the client's WireGuard IP.

### Architecture

```
Browser
  │
  ▼
Production Server (10.10.0.1)
  │  WireGuard tunnel (UDP 51820)
  ▼
Local Machine (10.10.0.2)
  │
  ▼
LM Studio API (port 1234)
```

## Part 1: Server Setup

### Install WireGuard

**CentOS/RHEL:**
```bash
sudo dnf install -y wireguard-tools
```

**Debian/Ubuntu:**
```bash
sudo apt update && sudo apt install -y wireguard
```

### Generate Server Keypair

```bash
cd /etc/wireguard
umask 077
wg genkey | tee server_private.key | wg pubkey > server_public.key
```

### Create `/etc/wireguard/wg0.conf`

```ini
[Interface]
Address = 10.10.0.1/24
ListenPort = 51820
PrivateKey = <contents of server_private.key>

[Peer]
# Local machine running LM Studio
PublicKey = <client_public_key>   # filled in after Part 2
AllowedIPs = 10.10.0.2/32
```

### Open Firewall and Start Service

**CentOS/RHEL (firewalld):**
```bash
sudo firewall-cmd --permanent --add-port=51820/udp
sudo firewall-cmd --reload
```

**Debian/Ubuntu (ufw):**
```bash
sudo ufw allow 51820/udp
```

**Enable and start:**
```bash
sudo systemctl enable wg-quick@wg0
sudo systemctl start wg-quick@wg0
```

## Part 2: Client Setup (Windows)

> **Important:** Install WireGuard on **Windows**, not inside WSL2. LM Studio runs on the Windows network stack, so the WireGuard virtual adapter must be on the same side.

### Install WireGuard for Windows

Download and install from [wireguard.com/install](https://www.wireguard.com/install/).

### Generate Keypair and Configure Tunnel

1. Open WireGuard → **Add Tunnel** → **Add empty tunnel…**
2. WireGuard auto-generates a private/public keypair — copy the public key
3. Paste this config (replace placeholders):

```ini
[Interface]
PrivateKey = <generated by WireGuard app>
Address = 10.10.0.2/24
DNS = 1.1.1.1

[Peer]
PublicKey = <contents of server_public.key from Part 1>
Endpoint = <your-server-ip>:51820
AllowedIPs = 10.10.0.1/32
PersistentKeepalive = 25
```

4. Save the tunnel.

---

## Part 3: Exchange Public Keys

Go back to the server and fill in the `[Peer] PublicKey` in `wg0.conf` with the Windows public key from Part 2, then restart:

```bash
sudo systemctl restart wg-quick@wg0
```

Then click **Activate** in the WireGuard Windows app.

---

## Part 4: Verify Connectivity

Check tunnel status on the server:
```bash
sudo wg show
```

The peer should show a recent handshake. Then confirm LM Studio is reachable:
```bash
curl http://10.10.0.2:1234/v1/models
```

This should return a JSON list of loaded models.

> **Note:** `ping 10.10.0.2` will likely fail — Windows Firewall blocks ICMP by default. A successful `curl` is the correct test.

## Part 5: LM Studio Configuration

In LM Studio's **Server** tab:

- Set the server to listen on **all interfaces** (`0.0.0.0`), not just `127.0.0.1` — otherwise the WireGuard adapter cannot reach it
- Note your **API key** if you have one configured (LM Studio supports optional API key auth)
- Note the exact **model identifier** shown in the server tab (e.g., `publisher/model-name-GGUF`)

## Part 6: Laravel AiSystem Configuration

Create an `AiSystem` record pointing at the LM Studio endpoint. The existing `OpenAiService` handles all OpenAI-compatible providers.

### Via Tinker

```bash
php artisan tinker
```

```php
\App\Models\AiSystem::create([
    'provider'           => 'openai-compatible',
    'base_url'           => 'http://10.10.0.2:1234/v1',
    'api_key'            => '<lm-studio-api-key>',   // leave empty string if no key
    'model'              => '<model-identifier>',
    'max_tokens'         => 2048,
    'is_local_endpoint'  => true,
    'is_active'          => true,
]);
```

### Via Admin UI

Navigate to the AI Systems admin page and create a new system with:

| Field | Value |
|-------|-------|
| Provider | OpenAI Compatible |
| Base URL | `http://10.10.0.2:1234/v1` |
| API Key | your LM Studio API key |
| Model | model identifier from LM Studio |
| Is Local Endpoint | true |
| Is Active | true |

## Keeping the Tunnel Alive

The tunnel depends on the WireGuard Windows client staying active. To make it persistent:

- In the WireGuard Windows app: check **Launch WireGuard on startup**
- Set the tunnel to auto-connect on startup
- The `PersistentKeepalive = 25` in the client config ensures the tunnel stays open through NAT even when idle

To check tunnel health from the server at any time:
```bash
sudo wg show
# Look for "latest handshake" — should be within the last few minutes
```

## Performance Notes

WireGuard encryption overhead is negligible (~1–3ms). The real performance factors are:

- **LM Studio inference speed** — your local GPU/CPU generating tokens is usually the bottleneck
- **Home internet upload speed** — LM Studio responses travel from your machine up through your ISP to the server; slow upload (< 20 Mbps) will be noticeable for long responses
- **Streaming** — the app uses SSE streaming, so tokens appear progressively rather than waiting for the full response, which makes latency much less painful in practice

For faster inference, consider using a quantized model (Q4 or Q5 GGUF) in LM Studio.
